Getting started ​

julia
using Pkg
Pkg.add("UpdatableFactorizations")

Cholesky ​

UpdatableCholesky factors a Hermitian positive definite matrix. It can be built from a plain matrix or from an existing LinearAlgebra.Cholesky; both input orientations, uplo = :L and uplo = :U, give identical results because the package always stores the lower factor.

julia
using LinearAlgebra, UpdatableFactorizations

A = [4.0 2.0; 2.0 3.0]
F = UpdatableCholesky(A)
F.L
2×2 LinearAlgebra.LowerTriangular{Float64, SubArray{Float64, 2, Matrix{Float64}, Tuple{UnitRange{Int64}, UnitRange{Int64}}, false}}:
 2.0   ⋅ 
 1.0  1.41421

F.U is the adjoint of F.L, and Matrix(F) reconstructs A:

julia
F.U
2×2 LinearAlgebra.UpperTriangular{Float64, LinearAlgebra.Adjoint{Float64, SubArray{Float64, 2, Matrix{Float64}, Tuple{UnitRange{Int64}, UnitRange{Int64}}, false}}}:
 2.0  1.0
  ⋅   1.41421
julia
Matrix(F) ≈ A
true

F supports the standard Factorization interface — \, ldiv!, size, det, logdet:

julia
b = [1.0, 2.0]
F \ b
2-element Vector{Float64}:
 -0.12499999999999994
  0.7499999999999999

LU ​

UpdatableLU factors a general square matrix, with partial pivoting by default. It is stored as P*A = L*Diagonal(d)*U, but F.L and F.U return the factors in the same form LinearAlgebra.lu gives them, so the two are interchangeable for reading off the factorization.

julia
using LinearAlgebra, UpdatableFactorizations

B = [4.0 3.0; 6.0 3.0]
G = UpdatableLU(B)
G.L
2×2 LinearAlgebra.UnitLowerTriangular{Float64, Matrix{Float64}}:
 1.0        ⋅ 
 0.666667  1.0
julia
G.U
2×2 LinearAlgebra.UpperTriangular{Float64, Matrix{Float64}}:
 6.0  3.0
  ⋅   1.0
julia
Matrix(G) ≈ B
true

G.info and issuccess(G) report whether the factorization is still valid; see Updating and downdating for what invalidates it.

QR ​

UpdatableQR factors an m by n matrix with m >= n as Q*R, holding the thin Q (m by n, orthonormal columns) and the upper triangular R.

julia
using LinearAlgebra, UpdatableFactorizations

C = [1.0 1.0; 1.0 2.0; 1.0 3.0]
H = UpdatableQR(C)
H.R
2×2 LinearAlgebra.UpperTriangular{Float64, SubArray{Float64, 2, Matrix{Float64}, Tuple{UnitRange{Int64}, UnitRange{Int64}}, false}}:
 -1.73205  -3.4641
   ⋅       -1.41421

H.Q has orthonormal columns and Matrix(H) reconstructs C:

julia
H.Q' * H.Q ≈ I
true
julia
Matrix(H) ≈ C
true

Because the factorization is thin and m may exceed n, \ solves the least-squares problem rather than a square system:

julia
y = [1.0, 2.0, 2.0]
H \ y
2-element Vector{Float64}:
 0.6666666666666673
 0.49999999999999967

capacity is a tuple here, since a QR factorization grows in both directions — insert_row! adds an observation and insert_column! adds a variable:

julia
H2 = UpdatableQR(C; capacity = (10, 4))
UpdatableFactorizations.capacity(H2)
(10, 4)

capacity is public but not exported, so it is reached through the module name.

Capacity ​

UpdatableCholesky and UpdatableQR can grow: insert_column! extends the factored matrix by one index. The capacity keyword sets how large the factorization can grow before its storage is reallocated — an integer for UpdatableCholesky, a (rows, columns) tuple for UpdatableQR:

julia
F2 = UpdatableCholesky(A; capacity = 10)
size(F2)
(2, 2)

UpdatableLU has no resizing operation and so takes no capacity argument.
